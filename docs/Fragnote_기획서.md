# Fragnote 기획서 (v6)

## 0. 선행 작업: 데이터 시딩 계획
- 향수 마스터 DB는 공개 API가 없어 **수작업 시딩**이 필수 선행 작업
- 1차 범위: 100~200개 (예: 올리브영/시코르 인기 향수 위주로 선정)
- 브랜드, 향수명, 노트 구성(탑/미들/베이스), 이미지 URL을 CSV로 정리 → Prisma seed script로 삽입
- **날씨→노트 매핑 룰**도 이 단계에서 함께 정리 (향수 커뮤니티에서 통용되는 "여름/겨울 향수" 분류 기준 조사 후 룰 테이블화)
- **MVP에서는 사용자 직접 등록 기능 제외**, 시딩된 고정 카탈로그 내에서만 검색/등록 가능. 검색 결과가 없을 경우 "현재 지원하지 않는 향수예요" 안내 문구 명시 (버그로 오인 방지)
- 카탈로그 확장(신규 향수 추가)은 MVP 이후 seed script 재실행으로 처리, 별도 관리자 기능은 만들지 않음

## 1. 프로젝트 개요
- **프로젝트명**: Fragnote
- **컨셉**: 내 향수장(컬렉션) + 추천(취향 매칭 + 날씨 반영)
- **스택**: Next.js 풀스택 (App Router + Server Actions + Prisma)
  - 인증: Auth.js (NextAuth) — 카카오/구글 소셜 로그인
  - DB 호스팅: Neon (서버리스 PostgreSQL, Vercel 커넥션 풀 궁합 좋음)
  - 날씨 API: OpenWeatherMap (문서화 잘 되어 있고 무료 쿼터로 MVP 충분, 대안으로 기상청 API 검토 가능)
  - 이미지 스토리지: Vercel Blob (배포 환경과 궁합 좋아 별도 설정 부담 적음)
- **목적**: 포트폴리오 / 이직용 사이드 프로젝트
- **타겟 플랫폼**: 모바일 웹 우선, 반응형으로 데스크톱 대응

## 2. 유저 페르소나

| 항목 | 내용 |
|---|---|
| 이름 | 예린 (28세, 직장인) |
| 특징 | 향수 5~10개 보유, 상황별로 골라 뿌리는 편이나 매번 뭘 뿌릴지 고민 |
| Pain Point | 보유 향수를 기억 못 해 비슷한 향만 계속 씀, 새 향수 살 때 취향에 맞는지 확신 없음 |
| 기대 | 오늘 뭐 뿌릴지 고민 안 해도 되고, 내 취향에 맞는 새 향수를 쉽게 발견하고 싶음 |

## 3. 추천 엔진 설계 (통합)
- 코어: 향수-노트 벡터와 유저 취향 벡터 간 코사인 유사도 계산
- 파라미터로 동작 분기:
  - **취향 매칭 모드**: 유사도 순 정렬, 전체 카탈로그 대상
  - **데일리 모드**: 유사도 + 날씨 가중치(계절/기온별 노트 적합도, 0번 시딩 단계에서 정리한 룰 테이블 사용) + 최근 미사용 가중치 + 변질 위험(개봉 경과일) 가중치를 합산, **보유 향수 중에서만** 선정
- **빈 상태 폴백**: 보유 향수가 0개(신규 유저)일 때 데일리 모드는 자동으로 취향 매칭 모드로 폴백
- **추천 다양성 처리**: 최근 N일 내 이미 추천했던 향수는 우선순위를 낮춰서, 카탈로그가 작아도 매번 같은 상위 향수만 반복 추천되지 않도록 함
- **동일 향수 다중 보유 시 우선순위**: 같은 향수를 여러 `Collection` 항목(정품/미니어처 등)으로 보유한 경우, 잔량이 가장 적은 항목을 우선 추천 (다 쓰기 전에 소진하도록 유도). 잔량이 0인 항목은 후보에서 제외

## 4. 잔량(사용량) 계산 로직

### 4.1 자동 추정 + 수동 보정 하이브리드
```
사용 1회당 소모량(ml) = 스프레이 횟수 × 회당 분사량(기본 0.08~0.1ml)
잔량(ml) = 등록 시점 잔량 - Σ(이후 사용 로그별 소모량)
```
- 평소엔 자동 계산값 표시, 유저가 슬라이더로 수동 보정 가능
- 수동 보정 시 그 시점을 새 기준점으로 리셋, 이후 로그부터 다시 자동 차감
- 사용 로그를 수정/삭제하면 해당 향수의 전체 로그를 다시 순회해 잔량을 재계산 (실시간 차감 방식보다 느리지만 데이터 정합성 보장)

### 4.2 신규 향수 vs 사용하던 향수 등록
- 등록 폼에서 "이미 쓰던 향수인가요?" 분기
  - 새 향수 → 잔량 100%로 자동 세팅
  - 쓰던 향수 → 5단계 프리셋(새 것/약간 사용/절반/얼마 안 남음/거의 다 씀) 또는 슬라이더로 초기 잔량 입력
- `isPreOwned` 플래그로 저장, 컬렉션 상세에 "등록 이전 사용 이력은 통계에 반영되지 않아요" 안내

### 4.3 동일 향수 다중 보유
- 같은 향수를 정품 + 여행용 미니어처 등으로 여러 개 보유하는 경우 지원
- `Collection`은 향수당 유니크가 아니라 **여러 항목 등록 가능**, 각 항목이 자체 `totalMl` 보유 (정품 100ml, 미니어처 10ml처럼 서로 다를 수 있음)

### 4.4 잔량 0% 처리
- 자동 아카이브하지 않고 "다 썼어요" 배지만 표시
- 컬렉션 목록에서 필터로 숨김 처리 가능

### 4.5 향 변질/유통기한 관리
- `Collection`에 `openedAt`(개봉일) 필드 추가
- 개봉 후 경과 개월 수를 기준으로 변질 위험도 표시 (예: 12개월 경과 시 "슬슬 확인해볼 때예요" 배지)
- 노트 계열(family)별 권장 사용 기한을 참고치로 데이터화 (시트러스/프레시 계열은 짧게, 우디/오리엔탈 계열은 상대적으로 길게)
- 데일리 추천 엔진에 "오래 안 뜯은 향수 우선" 가중치를 추가해, 변질 위험이 있는 향수를 자연스럽게 먼저 추천

## 5. 화면 설계

### 5.1 온보딩 / 로그인
- 소셜 로그인 버튼 (카카오, 구글)
- 노트 선호도 설문 (5문항 내외, 카드 선택형) + 프로그레스 바

### 5.2 홈
- 오늘의 추천 카드 (날씨 아이콘 + 추천 이유 + "다른 향수 보기")
  - 위치 권한 거부 시: 도시 선택 드롭다운 노출
  - 보유 향수 0개 시: 취향 매칭 결과로 폴백, 안내 문구 노출
- 하단: 최근 사용 로그 요약(3개)

### 5.3 컬렉션 목록
- 그리드/리스트 뷰 토글, 위시리스트 필터 탭
- 카드: 이미지, 이름, 브랜드, 잔량 프로그레스 바, 잔량 부족/다 씀 배지
- 동일 향수를 여러 개 보유 시 카드 별도 표시 (예: "라이트 블루 (정품)" / "라이트 블루 (미니어처)")

### 5.4 향수 등록
- 카탈로그 검색(자동완성) — 결과 없으면 "현재 지원하지 않는 향수예요" 안내
- "이미 쓰던 향수인가요?" 분기 → 잔량 프리셋/슬라이더 입력
- 용량(ml), 구매일, 가격, 사진(선택)

### 5.5 컬렉션 상세
- 향수 정보, 잔량 조정 슬라이더, 사용 로그 타임라인 (날짜, 날씨, 장소, 스프레이 횟수)
- `isPreOwned`인 경우 안내 문구
- "사용 기록 추가" 버튼 (스프레이 횟수 기본값 3회, 수정 가능)

### 5.6 추천 탭
- 취향 매칭 향수 리스트 (유사도 순), 매칭 노트 태그, 노트 계열 필터

### 5.7 향수 상세 (마스터 데이터)
- 브랜드, 전체 노트 구성 시각화, 유사 향수 추천
- 카탈로그 이미지(있을 경우) 표시, 없으면 색상 블록 아이콘으로 대체
- "컬렉션에 추가" / "위시리스트에 추가"

### 5.8 통계 대시보드
- 빈 상태 안내, 월별 사용 빈도, 계절별 패턴(Recharts), 최다 사용 향수 랭킹

### 5.9 마이페이지
- 취향 프로필 재설정, 표시 설정, 계정 정보
- (배포 고려 시) 위치 정보 수집 관련 고지 필요

## 6. 스키마 스케치 (v4)
```
User (id, email, provider, nickname, profileImageUrl, createdAt)

Brand (name, country)
Note (name, family)
Perfume (brandId, name, noteComposition, imageUrl)
PerfumeNote (perfumeId, noteId, position, intensity)

Collection (
  userId, perfumeId,
  totalMl,            // 이 개별 항목의 용량 (정품/미니어처 등 다를 수 있음)
  initialMl,           // 등록 시점 추정 잔량
  currentMl,           // 이후 로그로 계속 차감되는 현재 추정치
  isPreOwned,
  openedAt,            // 개봉일 (변질 위험도 계산용)
  lastAdjustedAt,
  purchasedAt, price,
  photoUrl             // 실물 사진 (선택)
)

Wishlist (userId, perfumeId)

UsageLog (
  userId, collectionId,  // perfumeId 아닌 collectionId 참조 (다중 보유 대응)
  date, weather, location, sprayCount
)

UserNotePreference (userId, noteId, weight)
```

## 7. MVP 우선순위
1. 데이터 시딩 (향수 카탈로그 + 날씨-노트 매핑 룰)
2. 온보딩 & 취향 설정
3. 컬렉션 등록/관리 (다중 보유, 신규/사용중 분기, 변질 관리 포함)
4. 추천 엔진 (데일리/취향 매칭 통합, 폴백·다양성·변질 가중치 포함)
5. 통계 대시보드 (여유 있으면 추가)

## 8. v2 이후 확장 검토 사항 (MVP 범위 아님)
- 레이어링(향수 2개 이상 혼합 사용) 지원
- 카탈로그 관리자 UI
- 실물 무게 기반 잔량 측정
- **향 궁합 테스트**: 두 유저의 취향 프로필을 비교해 궁합 지수 산출, 공유용 결과 카드 생성, 소셜 유입 실험 목적. 다인 매칭 로직·초대 시스템·이미지 카드 생성이 별도로 필요해 MVP 대비 작업량이 크므로(약 15~22시간 추정) v1.1 이후로 보류

## 9. 향수 카탈로그 유저 등록 확장 로드맵 (단계적 오픈 대비)

MVP는 고정 카탈로그만 지원하지만, 향후 소규모 오픈이나 대중 오픈까지 고려할 경우 아래처럼 단계적으로 유저 등록 기능을 확장한다.

| 단계 | 등록 방식 | 핵심 장치 |
|---|---|---|
| MVP (포트폴리오) | 고정 카탈로그만, 유저 등록 없음 | 시딩된 100~200개 카탈로그 내 검색만 허용 |
| 소규모 오픈 (지인/커뮤니티) | 유저 등록 허용 + 관리자 검수 큐 | 구조화된 입력 폼(브랜드/노트 선택형), 유사 항목 사전 검색으로 중복 방지, status(pending/approved)로 승인 전엔 본인에게만 노출 |
| 대중 오픈 | 커뮤니티 검증 + 신뢰도 시스템 | 동일 항목에 N명 이상 같은 값 입력 시 자동 승인, 계정 신뢰도(활동 이력 기반)로 어뷰징 방지, Rate limiting·신고 기능·스팸 자동 탐지, UGC 이용약관 정비, 이미지는 텍스트/아이콘 또는 본인 소유 실물 사진만 허용해 저작권 리스크 최소화 |

**대중 오픈 시 추가로 검토할 사항**
- 브랜드 데이터를 상업적 서비스에서 대량 활용하는 것에 대한 법률 자문 (사실 정보 자체는 저작권 보호 대상이 아니지만, 규모가 커지면 브랜드 측 문제 제기 가능성 있음)
- 모더레이션 인력 또는 반자동 스팸 탐지 도구에 대한 운영 비용
- 이미지 업로드 트래픽 증가에 따른 스토리지/CDN 비용
